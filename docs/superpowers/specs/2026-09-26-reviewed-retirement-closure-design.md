# Reviewed retirement closure for mixed Blueprint event graphs

- Date: 2026-09-26
- Status: Design awaiting written-spec approval; no code or Ripper asset mutation authorized by this document.
- Owner: UnrealCortex `CortexGraph` retirement migration and its MCP response contract.

## Intent and observed problem

RIP-44 moves Email behavior into native C++. The page's eight explicitly obsolete entries remain in a mixed EventGraph alongside four cosmetic hooks that must survive. The current guarded `retire_entries` preview scans 136 nodes and 392 links but reports 70 removable, 15 shared and nine blocked nodes. `OnInitialized` feeds an IsValid/retry cycle involving a macro and a latent call; the ListView selection path feeds a cast also reached from another old path. Applying only the removable subset would leave obsolete behavior. The user chose a Cortex guard extension rather than unguarded Editor deletion.

Success means a caller can preview and explicitly approve one exact, closed set of obsolete page nodes, retire the selected entry bindings and their proven-owned body, preserve unrelated cosmetic nodes and all retained graph links, compile and read back the result, and save only after verification. A refusal with no mutation is the correct result if ownership cannot be proven. This tool cannot itself establish that the native C++ implementation is behaviorally equivalent; RIP-44 still needs actual-PC runtime and persistence evidence.

## Decision and boundaries

Extend `graph.apply_patch(migration.op=retire_entries)` rather than adding general node deletion. Keep the existing `source.graph_ref`, `source.entry_node_guids`, `approved_node_guids`, graph fingerprint/validation hash, class-specific event guards, preservation capture, transaction/journal/rollback, compilation and explicit save/readback. Add an optional `source.additional_node_guids`: the caller names *only* obsolete, non-entry nodes that the default ownership partition retains or blocks. Missing field retains current behavior. Every listed GUID must be unique, resolve to exactly one node in the named top-level ubergraph, differ from the entry GUIDs and belong to the execution/data island of those entries. Do not infer redundancy from a node name, class, cached compiler error or proximity. No graph search may automatically add unrequested nodes to this override set.

The request is reviewed in two stages: a non-mutating preview with the same source fields, then an apply with the **identical** source fields, the preview's validation hash and `approved_node_guids` exactly equal to the newly computed complete removable set. The preview inventories entry identities and class-specific bindings, explicitly requested additional GUIDs with node class/reason, the full removable/shared/blocked partition, and every edge crossing the proposed deletion boundary. It also exposes whether the result is approval-eligible. No preview that truncates a required identity/edge list may be treated as an approval token; return an explicit refusal or a complete retrievable inventory instead of allowing approval from a shortened display. A changed graph, identity, list or edge set invalidates approval.

## Ownership proof

Recompute the island and graph-wide unique GUID ownership at preview and apply. A requested additional node can join the deletion candidates only if its class-specific removal semantics are supported by the Unreal Editor API, it does not own a graph that removal would orphan, and no external asset or retained graph consumer depends on it. Class families needed by the observed page (delegate binding, reroute knot, macro instance and latent call) are evaluated individually in sandbox fixtures before being admitted. A cycle may be removed only as a complete, explicitly reviewed closed set; a visited-set traversal is not by itself proof that a latent or macro node is safely removable. Any unproved class, subgraph ownership, pending PIE execution, ambiguous binding, surviving callable entry or cross-asset reference refuses the operation.

For each proposed removable node, inspect both execution and data links. An incoming execution edge from a retained entry/body, or an output consumed by a retained node, prevents deletion unless the *entire* obsolete dependent path is explicitly included and proven safe; retained cosmetic hooks cannot be sacrificed to close the set. Data producers used by retained consumers remain shared. For a retained input fed by a proposed removal, refuse rather than silently sever it. Expose each otherwise permitted boundary edge with endpoint GUID, pin name and direction for review, and verify the retained endpoints and link sets after mutation. Selected entries must all be removable; any unresolved blocked node in their execution path makes the full request ineligible. Do not bypass the current external-custom-caller scan or component-generated-binding verification.

## Execution and failures

Use the existing prepared request and journal; before removal require the same graph, complete untruncated approval set, unchanged fingerprint and source parameters, and stopped PIE. Remove only approved identities via supported Unreal editor node-removal APIs. Capture preserved nodes, pins, links and class-specific bindings before mutation. On removal, compile, readback or save failure, roll back the transaction and report its verified recovery state; unknown recovery blocks further editing. `compile=false, save=false` remains a staging result, never runtime proof; persistent retirement requires `compile=true` and successful post-compile readback before `save=true`. Entirely absent approved GUIDs may replay as already applied only under the existing all-absent identity rule; a mixed present/absent replay refuses. No automatic save of a partially compiler-invalid page.

## Verification and release gate

Add deterministic sandbox fixtures covering (1) a complete obsolete cycle with explicitly reviewed macro/latent/delegate nodes if their safe removal is demonstrable, (2) a ListView-style shared cast/data consumer that must be preserved or refused, (3) retained cosmetic hook and generated component binding preservation, (4) changed/missing/extra GUIDs, truncated inventories, unsafe bound graph and live PIE refusals, (5) rollback after injected remove/readback failure and idempotent replay. Run the relevant Graph automation group, full Graph suite, MCP bridge/router checks, and an isolated Editor preview/apply/readback/compile/save smoke. Review the plugin change before deploying into RipperGame; build the game Editor with its own Editor closed. Re-preview the real Email page against the deployed guard and approve nothing until its whole requested removal set and preserved edges have been inspected. If an observed node class cannot be proven safe, stop and surface the exact refusal rather than weakening the guard or mutating an asset manually.

The unrelated RipperMirror Editor, user-modified Quest Board and Email assets, and untracked template assets remain outside the plugin edit. A successful tool operation is only a prerequisite: page/detail/PC-host integration and actual-PC acceptance follow the approved RIP-44 plan.
