# Reviewed retirement closure for mixed Blueprint event graphs

- Date: 2026-09-26
- Status: Written design approved 2026-09-26; implementation plan and execution remain gated. No Ripper asset mutation authorized by this document.
- Owner: UnrealCortex `CortexGraph` retirement migration and its MCP response contract.

## Intent and observed problem

RIP-44 moves Email behavior into native C++. The page's eight explicitly obsolete entries remain in a mixed EventGraph alongside four cosmetic hooks that must survive. The current guarded `retire_entries` preview scans 136 nodes and 392 links but reports 70 removable, 15 shared and nine blocked nodes. `OnInitialized` feeds an IsValid/retry cycle involving a macro and a latent call; the ListView selection path feeds a cast also reached from another old path. Applying only the removable subset would leave obsolete behavior. The user chose a Cortex guard extension rather than unguarded Editor deletion.

Success means a caller can preview and explicitly approve one exact, closed set of obsolete page nodes, retire the selected entry bindings and their proven-owned body, preserve unrelated cosmetic nodes and all retained graph links, compile and read back the result, and save only after verification. A preflight refusal makes no mutation; an execution failure reports the actual in-memory and disk state. Refusal is the correct result if ownership cannot be proven. This tool cannot itself establish that the native C++ implementation is behaviorally equivalent; RIP-44 still needs actual-PC runtime and persistence evidence.

## Decision and boundaries

Extend `graph.apply_patch(migration.op=retire_entries)` rather than adding general node deletion. Keep the existing `source.graph_ref`, `source.entry_node_guids`, `approved_node_guids`, graph fingerprint/validation hash, class-specific event guards, preservation capture, transaction/journal/rollback, compilation and explicit save/readback. Add an optional `source.additional_node_guids`: the caller names *only* obsolete, non-entry nodes that the default ownership partition retains or blocks. Missing field retains current behavior. Every listed GUID must be unique, resolve to exactly one node in the named top-level ubergraph, differ from the entry GUIDs and belong to the execution/data island of those entries. Do not infer redundancy from a node name, class, cached compiler error or proximity. No graph search may automatically add unrequested nodes to this override set.

Approval has three steps: (1) a non-mutating discovery preview without `approved_node_guids` inventories the proposed removal; (2) after inspecting the *complete* inventory, the caller sends a second, non-mutating reviewed preview with `approved_node_guids` exactly equal to its removable set; (3) apply repeats the reviewed preview's source fields, approved GUIDs, patch ID and expected fingerprint, using the **reviewed preview's** validation hash. The hash includes approved GUIDs, so the discovery hash cannot authorize apply. The preview inventories entry identities and class-specific bindings, explicitly requested additional GUIDs with node class/reason, the full removable/shared/blocked partition, and every edge crossing the proposed deletion boundary. Native serialization must supply each review-critical identity and edge list in full or mark the preview approval-ineligible; its scan `complete` flag alone does not establish display completeness. The MCP bridge independently refuses responses exceeding its size bound. Neither a native trimmed list nor a shortened MCP response can authorize apply. A changed graph, identity, list or edge set invalidates approval.

## Ownership proof

Recompute the island and graph-wide unique GUID ownership at preview and apply. A requested additional node can join the deletion candidates only if its class-specific removal semantics are supported by the Unreal Editor API, it does not own a graph that removal would orphan, and no external asset or retained graph consumer depends on it. Class families needed by the observed page (delegate binding, reroute knot, macro instance and latent call) are evaluated individually in sandbox fixtures before being admitted. A cycle may be removed only as a complete, explicitly reviewed closed set; a visited-set traversal is not by itself proof that a latent or macro node is safely removable. Any unproved class, subgraph ownership, pending PIE execution, ambiguous binding, surviving callable entry or cross-asset reference refuses the operation.

Compute the retained/removable cut to a fixed point across both execution and data links, including cycles: whenever a node becomes retained, propagate its ownership constraints again before approval. A removable node may not have an incoming execution edge from a retained entry/body or an output consumed by a retained node; retaining a shared producer late in the walk must also recheck its execution consumers. An entire obsolete dependent path may be explicitly included only when its ownership is independently proven; never delete a shared producer or retained cosmetic hook merely to close the cut. Data producers used by retained consumers remain shared. For a retained input fed by a proposed removal, refuse rather than silently sever it. Expose each otherwise permitted boundary edge with endpoint GUID, pin name and direction for review, and verify retained endpoints and link sets after mutation. Selected entries must all be removable; any unresolved blocked node in their execution path makes the full request ineligible. Do not bypass the current external-custom-caller scan or component-generated-binding verification.

## Execution and failures

Use the existing prepared request and journal; before removal require the same graph, complete untruncated approved preview, unchanged fingerprint and source parameters, and stopped PIE. Remove only approved identities via supported Unreal editor node-removal APIs. Capture preserved nodes, pins, links and class-specific bindings before mutation. Removal, compilation or in-memory readback failure before disk commit uses journal rollback and reports its verified recovery state; unknown recovery blocks further editing. A save failure keeps the verified in-memory result dirty and reports that the file was not committed, without claiming rollback. A post-save verification failure reports that disk was committed but persistence remains unverified; do not undo the in-memory result or claim a disk rollback, and block mutation for the Editor process. Restart the Editor, reopen the saved asset and reconcile disk state before further authoring; reopening alone does not clear the guard. `compile=false, save=false` remains a staging result, never runtime proof; persistent retirement requires `compile=true` and successful post-compile readback before `save=true`. Entirely absent approved GUIDs may replay as already applied only under the existing all-absent identity rule; a mixed present/absent replay refuses. No automatic save of a partially compiler-invalid page.

## RIP-44 detail-screen admission

The page cut compiled and saved, but the detail EventGraph also contains an obsolete `UK2Node_AssignDelegate` and the exact UMGEditor `UK2Node_PlayAnimation` async proxy. Their owning classes are now admitted **only** as explicitly named `additional_node_guids`. AssignDelegate creates a separate custom event when placed; the event keeps its own GUID, ownership and retained-consumer checks and is not implicitly retired with the assignment. PlayAnimation has no bound graph or deletion override and expands to compiled proxy calls and delegates; removal requires a subsequent Blueprint compile before the asset is runtime-safe. Other assign/delegate derivatives, animation variants and async proxies remain blocked. The sandbox fixture covers discovery, exact approval, apply/readback, the preserved companion event and cosmetic hook; the full Cortex.Graph automation group must pass before deployment. These class exceptions do not approve a partial detail cut or bypass still-retained custom-event callers.

The detail AcceptButton branch also has an unexecuted `ShowQuestAssignCalendar` call whose execution input is disconnected but whose data input consumes the retiring cast. `additional_node_guids` may name that exact impure `UK2Node_CallFunction` only when it has no linked execution input, no linked output of any kind, and every linked data input is produced inside the already discovered island. It is added as a dead-end consumer, not as a new traversal seed. Pure, latent, proxy, executable, output-consumed and unrelated calls remain outside this exception. The regular graph-wide unique ownership, fixed-point retained-consumer partition, complete inventory, exact approval, compile/readback and rollback requirements still apply. No raw node removal API is added.

After retaining the calendar's component-bound notifications and rewiring them to native handlers, their former visibility setter starts a disconnected execution tail. The old `UpdateMessageDisplay` custom event cannot be retired while that tail still calls it. `retire_entries` therefore admits an explicitly selected exact `UK2Node_VariableSet` as a `disconnected_setter_root` only if every execution input is unlinked, at least one execution output feeds the obsolete tail, and it owns no subgraph. The existing graph-wide unique-GUID check, reverse producer and fixed-point retained-consumer partition, full reviewed cut, stale fingerprint, validation hash, compile requirement, readback and rollback still apply. A linked setter or another node class is refused. Retire this detached tail first; only then can the now-unreferenced custom event pass its ordinary in-asset and foreign-caller checks. The regression extends the existing sandbox retirement fixture with a retained cosmetic hook and shared producer; it fails before admission and passes after.

## Isolated automation package lifetime (2026-10-01)

The retirement `FFixture`, `FGuardedEntryFixture`, `FExternalCallerFixture` and rewire `FFixture` allocate packages through the shared private test-content helper. Each allocation uses `/Game/Temp/CortexGraphFixture_<full GUID>/<original asset leaf name>`. This preserves asset/class leaf names and dynamically captured paths while preventing reuse or deletion of a previous run's saved fixture package.

Disk cleanup belongs to the fixture destructor, not `Cleanup()`: existing persistence tests also use `Cleanup()` as an in-memory unload before reload/readback. Retain the owned package name through explicit unload, detach its resident loader before file deletion, delete only that fixture's `.uasset`, and remove only its empty GUID directory nonrecursively. Cleanup failures are automation errors. Final destruction also performs the existing in-memory cleanup; it does not add process-wide transaction resets, a different GC processor, broad child-object garbage marking or production cleanup behavior.

The deterministic partially-loaded fixed-package save failure establishes the package-isolation requirement. Passing fresh normal-GC queues establishes current candidate acceptance evidence, not the cause or resolution of the retained historical GC access violations.

Independent Python test cases represent independent authoring tasks. Reset the operation-schema correction budget at the shared pytest case boundary, not between calls within a case; preserve the production budget and the exhaustion contract. Live raw-TCP Level fixture/test requests use the advertised `spawn_actor.class_name` contract without changing the distinct `class` parameters of other Level operations. These are test-state and caller corrections only.
## 2026-10-01 review safety clarification

A matching foreign generated-function call or delegate whose owner cannot be proved makes caller evidence incomplete. Missing call owners and absent, multiply linked or non-object delegate scopes refuse retirement before approval; unrelated names and proved unrelated owners remain non-callers.

Call-output readback must preserve every unrelated incident call link. The prepared `call_links` inventory is mandatory even when empty: an empty inventory forbids adding unrelated links. Missing or malformed inventory refuses the prepared plan; any link divergence requires verified journal recovery.
